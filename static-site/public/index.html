Cloudflare Workers

Served from a folder, not a Pages project

This page, its stylesheet and the image below are static files inside public/. The Worker serves them directly, and there is no separate Pages project, build pipeline or origin server involved.

One deployment unit

Assets and the Worker script ship together with wrangler deploy. Nothing to keep in sync across two products.

Free for static requests

Requests that match a file are served from the edge cache and do not invoke the Worker script, so they do not count against Worker request limits.

Same origin as the API

Adding a main script to this config would let one Worker serve both the files and /api/*, with no CORS and no second domain.

Try a nested page or a path that has no file to see the single page application fallback. Note that /about/team.html answers with a 307 to /about/team: with the default html_handling the asset layer strips the extension, which is worth knowing before debugging a link that looks broken.
